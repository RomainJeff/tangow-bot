P5 token and cache measurements (S2)

The runner is the `measure` command of packages/testkit/src/cli/worker-live.ts. It drives the
protocol of native-harness-decisions.md ("P5 measurements") through the production executor,
worker routing, E2B worker provider, pi-native guest and model relay. Each model request is
recorded from the relay's agent.worker.model_request event: input, cache read, cache write and
output tokens, prompt bytes, bytes shared with the previous request, first divergent section.

Scenarios, one fresh controller database and thread each, one thread at a time:
  chain       short exchanges in one thread, separated by each --gaps value, order rotated per trial
  computer    a browser task on the bot's computer, then a short follow-up
  approval    a note publication that waits on approval, granted after each --approval-delays value
  compaction  three large exchanges, the thread's history.compact job, then two short exchanges
Each trial runs every model, rotating which goes first. The deployment's owned sandboxes and
volumes are swept after every thread, in a finally, and the count left is in the receipt.

The receipt also gives, per model and scenario, the list-priced cost of the measured stable
projection and an estimate of one persistent native session built from the same requests
(no persistent arm is run). The estimate is generous to the persistent session. If it is cheaper
by 15% or more, buildPersistentArm is true and a real persistent arm is built outside P5.
It also gives the restore latency after an approval outside provisioning, and the controller time
and database queries of each native transcript append.

Model
  Provider opencode-go through the user's model connection, a plain key on the catalog provider,
  as the product bills it. There is no provider- or model-specific variable.
  --models takes catalog patterns where * stands for a dotted version; the newest match wins.
  With the installed pi-ai 1.3.0, glm-*-flash resolves to glm-5.3-flash (openai-completions,
  cache-read price only) and gpt-*-luna to gpt-6-luna (openai-responses, cache-read and
  cache-write prices). Both use the catalog base URL https://opencode.ai/inference/go/v1; a
  smoke request confirmed gpt-6-luna on its /v1/responses route. Each request's reported cache
  read and write tokens are recorded, and each model's cache mode is summarized as observed.
  This model pair is the maintainer's choice and replaces the decisions document's "one explicit
  and one automatic provider". gpt-6-luna replaced DeepSeek V4.1 Flash, which requires the
  workspace's Global region setting.

Offline proof (no credential, no network)
  pnpm db:generate
  HOME=<temporary directory> pnpm exec vitest run --maxWorkers=2 \
    packages/testkit/src/worker-live/measure.test.ts
  The catalog entry points at the local model protocol fixture for the test's lifetime. The four
  scenarios run on the local worker provider, and the relay events become the receipt's records.

Computerless run without E2B
  RAKAZO_MODEL_KEY_FILE=<private key file> pnpm test:worker-live measure --worker local \
    --scenarios <chain|approval|compaction> --trials <n> --out <scratch>/proof
  Guests run in the controller process on one stable directory per thread; the key stays with
  the controller's relay. One stream per model runs at once, since each model's provider cache
  is its own.

Live run (needs the model key and the E2B forward)
  pnpm test:worker-live:bundle
  Copy packages/testkit/dist/worker-live to <scratch>/live, an owned scratch directory on the
  deployment host. Write the OpenCode Go key alone into a private file outside any git work tree
  (mode 600). The runner refuses a key file inside a work tree, and never prints the key or its
  path.
  Use the existing I1 probes/i1/with-e2b.sh wrapper for the E2B variables, as for P4. Then:
    RAKAZO_MODEL_KEY_FILE=<private key file> node <scratch>/live/bin/worker-live.mjs measure \
      --harness pi-native --guest <scratch>/live/guest/agent-run-worker.mjs \
      --template <worker template> --computer-template <desktop computer template> \
      --prepare-computer --out <scratch>/proof
  The computer scenario needs a computer template with a desktop and browser. Without one, pass
  --scenarios chain,approval,compaction and record the missing scenario as a limit.
  Defaults: --trials 30, --gaps 10s,2m,5m,10m, --approval-delays 10s,6m. The command prints
  the time its waits take before it starts: about 24 hours at the defaults. Scenarios can run as
  separate invocations with --scenarios. The receipt marks fewer than 30 trials as not comparable.
  token-cache.json is rewritten after every thread, so an interrupted run keeps a partial receipt.
  Copy <scratch>/proof/token-cache.json into this directory after checking it names no key,
  endpoint, account, machine or local path.
