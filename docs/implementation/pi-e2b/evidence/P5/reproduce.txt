P5 token and cache measurements (S2)

The runner is the `measure` command of packages/testkit/src/cli/worker-live.ts. It drives the
protocol of native-harness-decisions.md ("P5 measurements") through the production executor,
worker routing, pi-native guest and model relay, and records every model request from the
relay's agent.worker.model_request event. Each receipt's `method` block defines every figure.
  worker-live measure-summary --in <receipt> --out <receipt>
recomputes a receipt's method and summary from its own raw threads; every committed receipt
was rendered this way at the source that commits it.

Scenarios, each thread on a fresh controller database, bot and thread:
  chain       short exchanges in one thread, separated by each --gaps value, order rotated per trial
  computer    a browser task on the bot's computer, then a short follow-up
  approval    a note publication that waits on approval, granted after each --approval-delays value
  compaction  three large exchanges, the thread's history.compact job, then two short exchanges

Model
  Provider opencode-go through the user's model connection, a plain key on the catalog provider.
  No provider- or model-specific variable. --models takes catalog patterns where * stands for a
  dotted version; the newest match wins. With pi-ai 1.3.0, glm-*-flash resolves to glm-5.3-flash
  (openai-completions) and gpt-*-luna to gpt-6-luna (openai-responses), both on the catalog base
  URL https://opencode.ai/inference/go/v1; a smoke request confirmed gpt-6-luna on /v1/responses.
  gpt-6-luna replaced DeepSeek V4.1 Flash, which requires the workspace's Global region setting.
  The pair is the maintainer's choice and replaces the decisions document's "one explicit and one
  automatic provider".

Key
  The key sits alone in a private file outside any git work tree, named by RAKAZO_MODEL_KEY_FILE.
  The runner refuses a file inside a work tree and never prints the key or its path. On the
  deployment host the key travelled over ssh stdin to a private descriptor of the controller
  process only (RAKAZO_MODEL_KEY_FILE=/dev/fd/3); the I1 wrapper reads stdin itself, so the key
  cannot be passed as plain stdin. It was never written to the host and never reached a VM.

Overlapped computerless runs, local guests (token and cache counts only)
  RAKAZO_MODEL_KEY_FILE=<private key file> pnpm test:worker-live measure --worker local \
    --in-flight 10 --scenarios chain --trials 30 --gaps 10s,2m,6m --out <scratch>/chain
  ... --scenarios compaction --trials 30 --gaps 10s --out <scratch>/compaction
  ... --scenarios approval --trials 30 --gaps 10s --approval-delays 10s,6m --out <scratch>/approval
  Both models run at once, up to 10 trials in flight each; a rate-limited thread is rerun after
  backoff. Each thread's tool catalog carries its own nonce. Guests run in the controller process
  on one stable directory per thread. Restore and append timings from these runs are marked not
  comparable. Source 142143709; two earlier local attempts (serial, then overlapped without the
  tools' position) were set aside and are not in the receipts.
